# 트레이 아이콘 가독성 개선 계획 — 픽셀 폰트

> **상태: 구현 완료 (v0.4.0), 캡션 단위 개편과 라벨·단위 토글 제거 (§9).** 이 문서는 계획과 근거를 남긴다. 구현 결과는
> [PLAN.md](PLAN.md) §14, 실측은 [SPIKE.md](SPIKE.md) §12에 있다.

현재 아이콘은 **큰 Segoe UI를 8배 슈퍼샘플로 그린 뒤 16px까지 다운샘플**한다.
작은 크기에서는 안티에일리어싱(AA)이 획을 회색으로 번지게 해 라벨(5px)이 뭉개진다.
이 문서는 **1비트 픽셀 폰트**로 갈아타 가독성을 올리는 계획과, 그 근거로 만든
실험 결과를 정리한다.

- 실험 산출물(로컬, 커밋 안 함): `out/compare2.bmp`, `out/arrows.bmp`, `out/sheet-*.bmp`
- 관련 실측: [SPIKE.md](SPIKE.md) §1, §2, §2-1 / 로드맵: [PLAN.md](PLAN.md) §1

---

## 1. 현황 진단

파이프라인은 `src/icon/` 안에 격리되어 있다.

| 단계 | 코드 | 문제로 보는 지점 |
| --- | --- | --- |
| 래스터 | `gdi::rasterize` | Segoe UI semi-bold를 `max(box_w,box_h)*8`px로 렌더 |
| 크롭/축소 | `render::downsample` | 박스 필터 평균 → 최대값 정규화 |
| 레이아웃 | `layout::stack_spec` | 16px: 라벨 5 / 간격 1 / 값 9, 라벨 알파 190 |
| 캐시 | `cache::GlyphCache` | 문자열 단위, 히트율 59% |

16px 실측값은 라벨 5px, 값 9px다. 문제는 **높이가 아니라 획의 질**이다.

- 라벨은 5px 높이의 AA 다운샘플이라 `CPU`/`MEM`/`DN`/`UP`이 회색 덩어리로 보인다.
- 값은 `Fit::Squeeze`로 가로 압축까지 겹쳐 `1.2M` 같은 4글자가 더 뭉갠다.
- AA 결과가 Windows 버전·폰트 버전에 따라 달라져 **픽셀 테스트를 할 수 없다**
  (PLAN.md §14가 "픽셀 해시 비교는 하지 않는다"로 못 박은 이유).

## 2. 실험 결과 (1비트 픽셀 폰트)

가설 검증용으로 3x5(라벨) + 3x7(값) 1비트 글리프를 만들어 같은 조건으로 렌더했다
(임시 Python 프로토타입, 저장소에는 들어가지 않음). 비교 시트: `out/compare2.bmp`.

| 행 | 구성 | 관찰 |
| --- | --- | --- |
| 1 | 현재 GDI (16px) | 라벨이 회색으로 번짐, 값 가장자리 흐림 |
| 2 | 픽셀 3x5 + 3x7 | 라벨이 또렷, 값 획이 선명. **유력** |
| 3 | 픽셀 3x5 + 3x5 | 값이 작아 강조가 사라짐 |
| 4 | 픽셀, 4글자 값 | `100%` `1.2G` `999K` `512` 모두 16px에 들어감 |

**구현 후 조정:** 첫 구현의 값 높이는 7px였는데, 이전 GDI 렌더(9px)보다 작아 보인다는
평가를 받아 **값을 3x9(블록 15px)로 올렸다.** 높이는 이전과 같아지고, 폭은 3px 글리프라
좁다(`80%`=12px). 4글자가 16px에 들어가려면 글리프가 3px이어야 하므로 폭은 더 못 늘린다.

핵심 확인:

- **1비트라서 계조가 없다.** 1px 획이 배경과 정확히 2값으로 갈려 작은 크기에서 더 잘 읽힌다.
- **`%` 글리프가 관건이다.** 3x5 `%`는 `:`처럼 보였다. 3x9 값 폰트의 4x9 `%`가
  `80%`/`100%`/`0%`에서 또렷했다.
- **4글자 상한이 유지된다.** 값 폰트를 3px 폭으로 잡으면 `100%`=15px, `999K`=15px,
  `1.2M`=13px로 16px 안에 1px 간격까지 들어간다. 4px 폭 글리프는 `100%`=19px로 넘친다.
- **화살표 라벨이 다시 후보가 된다.** SPIKE.md §11에서 탈락시킨 `↓`/`↑`는 AA 때문에
  얇은 세로획이 뭉갠 것이었다. 1비트 3x5 화살표는 `out/arrows.bmp`처럼 선명하게 나온다
  (다만 지금은 `DN`/`UP` 텍스트가 더 명확해 보인다).
- **부수 효과**: 결과가 OS와 무관하게 결정론적이라 **정확한 픽셀 해시 테스트**가 가능해진다.
  GDI 텍스트 경로(`rasterize`)를 아이콘에서 제거할 수 있어 CI에서도 디스플레이가 필요 없다.

## 3. 제안 아키텍처

```
src/icon/
├── glyphs.rs   (생성물) 1비트 글리프 표 + 메타데이터
├── pixel.rs              GlyphSet, 문자열 측정/배치/블릿 (순수, GDI 없음)
├── layout.rs             px -> (GlyphSet, label_h, gap, value_h) 정책
├── render.rs             Bitmap/Color 유지, downsample/ink_bounds는 제거 대상
├── gdi.rs                bitmap_from_rgba(미리보기 합성)만 남김
└── cache.rs              키만 정리해 유지
tools/pixelfont.py        ASCII art -> glyphs.rs 생성 + --check
```

설계 원칙:

1. **글리프는 ASCII art로 쓰고 생성기가 Rust 표로 바꾼다.** `tools/make_assets.py`처럼
   `--check`를 두어 커밋된 표가 낡지 않게 한다. 글리프 편집이 코드 diff로 보인다.
2. **픽셀 폰트는 순수 함수다.** `render_text` 대신 `pixel::draw(text, set, rect)`.
   단위 테스트에서 픽셀 해시와 잉크 bbox를 검증한다.
3. **레이아웃 정책은 master(폰트 크기) 선택으로 바뀐다.** `Fit`(Uniform/Squeeze)은 없어진다.
4. **캐시는 유지한다.** 키에서 `fit`을 빼고 `(text, set, color, alpha)`만 남긴다.
   히트율이 그대로 상승 효과를 낸다.
5. **미리보기(`settings/preview.rs`)는 그대로 동작한다.** `icon::stacked`가 바뀌면
   자동으로 새 렌더러를 쓴다.

### 글리프 커버리지

실제로 필요한 문자만 넣는다(누락 시 `?` 폴백). 라벨이 지표 이름(`CPU`/`MEM`/`GPU`/`VRM`),
단위(`B`/`K`/`M`/`G`), 방향(`↓`/`↑`)뿐이므로 **캡션 12자 + 값 11자**면 충분하다
(`?`는 두 표가 공유해 글리프는 25개다). 글리프가 적을수록 유지보수가 쉽다.

- 캡션 문자(`LABEL`, 3x5): `C P U M E G V R B K ↓ ↑` (12자)
- 값 문자(`VALUE`, 4x10): `0–9 .` (11자)
- `%`는 그리지 않는다. 값이 백분율인 지표는 캡션 이름이 단위를 대신한다(§9)
- 여유가 되면 `A–Z`로 넓히되, 처음부터 전체를 그리지 않는다

### 폰트 라이선스 (결정 필요)

| 안 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 직접 제작 (권장) | 위 커버리지를 자체 1비트 글리프로 | 완전 자유(MIT), 크기 최적화, 의존 없음 | 디자인 작업 필요 |
| B. 오픈 폰트 임베드 | Cozette(MIT)·m3x6/m5x7·Silkscreen(OFL) 등 | 디자인 품질 | 라이선스 고지, 글리프 커버리지/굵기 검증 필요 |
| C. Windows 비트맵 폰트 | `Small Fonts` 등 GDI 비트맵 폰트 | 코드 최소 | OS 의존, 크기 제어 한계, 이식성 없음 |

A를 기본으로 하고, 필요하면 B의 글리프를 참고(라이선스 준수)한다. C는 채택하지 않는다.

## 4. 레이아웃 후보 (시트로 판정)

### 왜 임베드 픽셀 폰트인가 (GDI 네이티브 실측)

대안으로 “GDI를 슈퍼샘플 없이 네이티브 크기로, `NONANTIALIASED_QUALITY`로 그리기”를
측정했다(`out/gdi_native.bmp`, `out/icon_native.bmp`).

| 관찰 | 결과 |
| --- | --- |
| 계조 | Segoe UI·Tahoma·Consolas·Small Fonts·Terminal·Fixedsys 모두 **2계조(1비트)** |
| 5px 라벨 | 모든 폰트에서 획이 끊겨 깨짐 (`CPU`→`ОНU`) |
| 9px 값 | `80%`가 18~20px, 4글자는 더 넓어 **16px를 넘침** |
| 7px 라벨 | 읽히지만 3글자가 14px로 간신히 들어감 |

GDI는 배율별 hinting을 해 주므로 유지보수가 가장 쉽지만, **폭 예산을 못 맞춘다.**
`1.2M`을 16px 안에 넣으려면 글리프가 3px 폭이어야 하는데 시스템 폰트는 5~6px다.
그래서 좁게 설계된 1비트 글리프를 임베드하고, 배율은 우리가 제어한다.

### 스케일 정책 (핵심)

`SM_CXSMICON = 16 × dpi/96` 이므로 크기는 16/20/24/28/32/36/40/48 …이다.
**비정수 배율에서 1비트 폰트의 획 두께는 균일할 수 없다.** 1.25px 두께의 균일한 획은
존재하지 않아 1px·2px이 섞인다. 실측(`out/scale.bmp`)에서도 16·32px은 균일,
20·24·28px은 들쭉날쭉하다. 이는 구현이 아니라 수학적 한계다.

그래서 **master는 하나(16px 설계)로 두고, 모든 크기를 스케일로 처리**한다.
유지보수성을 위해 배율마다 글리프를 새로 만들지 않는다.

| px | 배율 | 스케일 | 특징 |
| --- | --- | --- | --- |
| 16 | 100% | 1x | 원본, 균일 |
| 20 | 125% | NN 1.25x | 셀을 채움, 획 ±1px |
| 24 | 150% | NN 1.5x | 셀을 채움, 획 ±1px |
| 28 | 175% | NN 1.75x | 셀을 채움, 획 ±1px |
| 32 | 200% | 2x | 균일 |
| 36+ | | 정수배 + 여백 (§10) | 36=2x+2, 40=2x+4, 48=3x |

- **불변식**: 렌더 결과는 항상 1비트다. AA/회색 계조가 섞이면 실패다(현재 버그의 원인).
- **품질 목표**: “깨지지 않고 또렷하다”. 비정수 배율의 획 ±1px 들쭉날쭉은 허용한다.
- **업그레이드 경로**: 24px(150%, 가장 흔한 비-100% 배율)의 들쭉날쭉함이 시트에서
  거슬리면 그 한 크기에만 master를 하나 더 둔다. 20/28/40은 그래도 비정수가 남으므로
  DPI별 master는 채택하지 않는다.
- **2x 이상 (§10에서 변경)**: 32px보다 크면 NN 대신 정수배 + 여백으로 그린다.

### 16px 후보 (시트로 판정)

| 후보 | 구성 | 블록 | 비고 |
| --- | --- | --- | --- |
| **V1 (권장)** | 라벨 3x5 + 간격 1 + 값 3x9 | 15 | 이전(9px 값)과 높이 동일. **채택** |
| V2 | 라벨 3x5 + 간격 0 + 값 3x9 | 14 | 값에 1px 더, 라벨/값이 붙음 |
| V3 | 라벨 3x5 + 간격 1 + 값 3x5 | 11 | 값 강조 없음(대조군) |

검증 시트: `out/scale.bmp`(배율별), `out/compare2.bmp`(16px 후보), `out/arrows.bmp`(화살표).

값 표기 제안(정보 손실 없이):

- `%`: 4x9 글리프로 유지한다. 다만 **단위 생략 토글**(`show_units`)을 둔다. 끄면
  숫자만 남아(`80`/`24`/`1.2`) 값이 3글자 이하가 되고, 그 폭을 값 글리프를 키우는 데 쓴다.
- 네트워크 단위: `K/M/G` 접미사를 유지한다. `show_units`를 끄면 접미사만 빠진다
  (`1.2M` → `1.2`, `24M` → `24`, `512` → `512`). 크기 자체는 그대로다.
- 채택 안 함: 라벨을 `↓`/`↑` 화살표로 바꾸고 값 높이를 키우는 안. `out/arrows.bmp`에
  비교만 남긴다(§7에서 텍스트 라벨 유지로 확정).

## 5. 검증 루프

1. `make validate` — fmt / clippy(`-D warnings`) / test. 픽셀 렌더러는 디스플레이 없이 테스트된다.
2. `make dump` 확장 — 렌더러별·레이아웃 후보별 시트를 한 번에 만들고
   `tools/icon_sheet.py`로 합친다. 판정 기준:
   - 잉크가 16x16 박스를 벗어나지 않는다
   - 라벨/값 줄 높이가 `layout` 정책과 일치한다
   - 실제 값 집합(`0%`…`100%`, `0`…`1.2G`)이 모두 박스에 들어간다
3. 새 테스트:
   - 글리프 표: 모든 문자 정의, 행 길이 일치, 커버리지 누락 없음
   - `pixel::measure`/`draw`: 알려진 문자열의 bbox와 **픽셀 해시**
   - 사이즈 매트릭스: 모든 px에서 블록 ≤ px, 라벨/값 최소 높이 보장
4. 눈 판정: `out/sheet-dark.bmp` / `out/sheet-light.bmp`를 16배 확대해
   밝은/어두운 작업 표시줄 양쪽에서 확인(AGENTS.md 검증 루프).

## 7. 확정된 결정

| 항목 | 결정 |
| --- | --- |
| 폰트 출처 | **A 직접 제작.** 필요 문자만 자체 1비트 글리프로 만든다(MIT 유지, 외부 의존 없음) |
| 라벨 | **텍스트 라벨 유지.** `CPU`/`MEM`/`DN`/`UP`을 1비트 3x5로 또렷하게. 색은 보조 단서 |
| 라벨/단위 표시 | **각각 토글 가능.** `show_labels`를 끄면 라벨 줄을 빼고 값 글리프가 커지며, `show_units`까지 끄면 값이 3글자 이하가 되어 4x13(`VALUE_HUGE`)으로 더 커진다 |
| 20px(125%) | **단일 16px master를 NN 1.25x.** 획 ±1px을 허용하고 셀을 채운다 |
| 32px(200%) | **단일 16px master 정수 2배.** 균일 |

> 배율 정책의 근거와 매트릭스는 §4 “스케일 정책”에 있다. **master는 하나**이고,
> 배율마다 글리프를 만들지 않는다. 비정수 배율의 ±1px 들쭉날쭉은 감수하고,
> “1비트(회색 없음), 깨지지 않음”을 지킨다. GDI 네이티브 비AA는 §4에서
> 폭 예산 때문에 탈락했다(측정).

화살표 라벨(`↓`/`↑`)과 값 확대 안은 채택하지 않는다. 필요하면 `out/arrows.bmp`로
비교만 남겨 둔다.

## 8. 결과

- 구현: `src/icon/{glyphs,pixel,layout,render,cache}.rs`와 `tools/pixelfont.py`.
- 검증: `cargo test` 132개 통과, `make dump` 시트에서 16/20/24/32px 모두 1비트
  (`[190, 255]`) 확인, 밝은/어두운 작업 표시줄 양쪽 시트를 눈으로 판정.
- 기존 GDI 텍스트 경로(`rasterize`/`downsample`)는 제거했고, `gdi.rs`에는 미리보기용
  `bitmap_from_rgba`만 남았다.
- 남은 선택지: 24px(150%)의 들쭉날쭉함이 거슬리면 그 크기 전용 master를 추가한다.
- **라벨/단위 토글**: 트레이 메뉴·설정 창(`Show labels`, `Show units`)·`config.toml`
  (`show_labels`, `show_units`)로 켜고 끈다. 값 글리프는 세 단계다 — 라벨 표시
  3x9(블록 15px) → 라벨 숨김 + 단위 표시 4x10(블록 10px) → 라벨·단위 모두 숨김
  4x13(블록 13px). 단위를 숨기면 값이 3글자 이하가 되는 점을 폭으로 바꾼다.

## 9. 개편: 단위를 캡션으로 올린다

§8의 결과를 16px에서 다시 보니 세 곳이 덜 읽혔다(`make dump` 시트로 판정).

- **`%` 글리프**: 4x9 대각선이 `?`나 `2`처럼 보이고, 값 줄 16px 중 5px를 먹었다.
- **3px `M`/`N`**: 대각선을 넣을 자리가 없어 `MEM`이 `HEH`, `DN`이 `DH`로 읽혔다.
- **라벨 숨김 + 단위 표시(4x10, 간격 0)**: 글자가 붙어 `100%`, `999K`가 한 덩어리로 보였다.

원인은 값 줄이 숫자와 단위를 함께 담아 4글자를 감당해야 한다는 데 있었다. 그래서
**단위를 캡션 줄로 올린다.**

| 지표 | 캡션 | 값 |
| --- | --- | --- |
| CPU / Memory | `CPU` / `MEM` (`%`는 자명해 생략) | `80` |
| Network down / up | `↓MB` / `↑KB` (방향 + 단위) | `1.2` |

- **값**은 숫자와 `.`만, 최대 3글자다. 4px 숫자에 1px 간격(`100`=14px)을 쓴다.
  블록은 캡션 5 + 간격 1 + 값 10 = 16px로 master를 꽉 채운다.
- **캡션**은 3x5 그대로 두되 `M`은 5px로 넓혔다. 가장 넓은 캡션은
  `MEM`·`↓MB`·`↓GB`로 15px다.
- **화살표**: §7에서 `DN`/`UP`을 유지했지만, 단위와 함께 3글자에 넣으려면 방향을
  1글자로 줄여야 한다. 1비트 3x5 `↓`/`↑`는 또렷하다(§2).
- **정보 손실 없음**: 방향·단위 배율(B/K/M/G)·숫자가 모두 남는다. 단위가 `K`에서
  `KB`로 바뀐 것은 캡션 폭에 여유가 생겨서다.
- **캐시**: 캡션은 지표당 많아야 4개(`B`/`KB`/`MB`/`GB`)라 히트율에 영향이 없다.
- **토글 제거**: §7·§8의 `show_labels`/`show_units`는 값을 키우려고 라벨·단위를 빼는
  장치였다. 값이 항상 3글자가 되면서 키울 이유가 사라져 둘 다 뺐다. 예전 `config.toml`의
  두 키는 읽을 때 무시하고 다시 쓰지 않는다.
- 글리프 표는 두 벌(캡션 3x5, 값 4x10)이다. 3x9·4x13 값 표와 `VALUE_LARGE`는 없어졌다.

## 10. 2x 이상은 정수배 + 여백 (v0.11.0)

225%(36px)에서 아이콘이 흐릿하다는 보고가 있었다. 원인은 두 가지였다.

1. **크기를 시작할 때 한 번만 쟀다(흐릿함의 원인).** PerMonitorV2에서
   `GetSystemMetrics(SM_CXSMICON)`은 시작 시점 DPI에 묶인다. 실행 중에 배율을 바꾸면 16px
   비트맵을 셸이 36px로 보간해 늘렸다. 지금은 작업 표시줄 DPI로 매 틱 다시 재고 크기가
   바뀌면 전부 다시 그린다([SPIKE.md](SPIKE.md) §16, AGENTS.md 규칙 25).
2. **36px는 NN 2.25x였다(거칢).** run 길이가 2와 3으로 섞여 획 두께가 들쭉날쭉했다.

2는 master를 새로 만들지 않고 배율 정책만 바꿔 해결한다(`render::fit`).

| px | 배율 | 이전 | 이후 | 글자 크기 |
| --- | --- | --- | --- | --- |
| 16 / 32 / 48 | 100 / 200 / 300% | 정수배 | 정수배 | 100% |
| 20 / 24 / 28 | 125~175% | NN | NN (그대로) | 100% |
| 36 | 225% | NN 2.25x | **2x + 사방 2px 여백** | 89% |
| 40 | 250% | NN 2.5x | **2x + 4px** | 80% |
| 44 | 275% | NN 2.75x | **2x + 6px** | 73% |
| 52 / 56 | 325 / 350% | NN | **3x + 2 / 4px** | 92 / 86% |

- **규칙**: `px / 16 >= 2`면 가장 큰 정수배로 그리고 남는 픽셀을 가운데 정렬 여백으로 둔다.
  1배밖에 안 들어가는 20~28px는 여백이 20~43%가 되어 너무 작아지므로 NN으로 셀을 채운다.
- **판정**: 36/40/44px에서 NN과 정수배 + 여백을 나란히 놓고 양쪽 배경에서 봤다. NN은
  `MEM`의 `M`과 `↓`의 획이 두께 2/3px로 섞여 얼룩지고, 정수배는 작아도 획이 고르다.
  44px(73%)는 작아진 게 눈에 띄지만 275%는 드문 배율이라 규칙을 하나로 유지했다.
- **여백 배분**: 캡션과 값 사이로 나누는 안도 있었지만, 줄 간격만 벌어지면 두 줄이
  다른 아이콘처럼 떨어져 보여 가운데 정렬로 둔다.
- **검증**: `icon::tests::large_sizes_keep_uniform_strokes`가 32~64px에서 모든 가로·세로
  run이 배율의 배수인지 본다. `make dump`는 16~48px 여덟 크기를 시트로 만든다.
