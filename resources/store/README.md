# Store assets

Assets for the Microsoft Store listing of **TinyTrayMonitor** (Partner Center → Store listing).

| File | Use |
| --- | --- |
| `StoreLogo300.png` | Store logo (300x300). Generated by `tools/make_assets.py`. |
| `listing.md`, `listing.ko.md`, `listing.ja.md` | Listing copy for en-US, ko-KR and ja-JP. |
| `screenshots/<lang>/01-taskbar.png` | The hero shot: a real Windows 11 taskbar with the eight readouts pinned, a magnified callout with labels, and the headline. |
| `screenshots/<lang>/02-settings.png` | The settings window in that language at 1:1, with the headline copy and the eight readouts. |
| `screenshots/<lang>/03-tray.png` | The eight readouts enlarged, each with its label. |

Screenshots are 1920x1080 (16:9). Partner Center requires at least one screenshot of
1366x768 or larger.

Regenerate the logo with `python tools/make_assets.py`.

## Screenshots

All screenshots are composed by `tools/store_shots.py` from pixels the app and Windows drew
themselves, never drawn by hand. The script skips any shot whose input is missing from `out/`, so
re-capturing one input regenerates only that shot.

The taskbar shot (`01-taskbar.png`):

1. Set the display scale to **225%** (the app draws the 16px master at 2x, so the icons stay
   crisp), turn off *Show accent colour on Start and taskbar*, and pin the eight readouts.
2. `powershell -File tools/capture_screen.ps1` writes `out/screen.png` at physical resolution.
   Windows PowerShell is not DPI aware, so the script switches to PerMonitorV2 first; without it
   the capture comes out scaled.
3. `TASKBAR` in `tools/store_shots.py` holds the column ranges measured on that capture (apps,
   tray, network/volume, the eight icons). Re-measure after a new capture. The IME indicator and
   the clock are cut because they differ per language; personal apps and notification badges are
   left out. The foreground is moved onto the new background as a difference from the acrylic
   background of each column.

The settings and tray shots:

1. `cargo build --release`, then `target
elease	iny-tray-monitor.exe --dump` writes the 16px
   tray icons to `out/dark_px16_<TAG>@16x.bmp`.
2. For each of `en`, `ko`, `ja`: set `language` and `ui_theme = "dark"` in
   `%APPDATA%\TinyTrayMonitor\config.toml`, start the app with `--settings`, and capture the
   dialog with `PrintWindow` (`PW_RENDERFULLCONTENT`) to `out/shot-<lang>.png` so overlapping
   windows do not end up in the crop.
3. `python tools/store_shots.py` (needs Pillow) writes `screenshots/<lang>/`. The icons are
   enlarged with nearest-neighbour only: they are drawn with a 1-bit pixel font, so any smooth
   interpolation blurs them.

Re-capture after a visible UI change; the `v<version>` label in the dialog is visible in
`02-settings.png`.

## Uploading to Partner Center

Screenshots go in through `Start update` → Store listings → each language → *Screenshots* →
`Save`, then `Submit for certification` (never the **Store** workflow; see
`docs/RELEASE-AUTOMATION.md` §8-9). Measured on Submission 16 (2026-10-26):

- New screenshots are appended in the order their upload *finishes*, not the order they were
  picked. Add one file, wait until its card appears, then add the next; a large file started
  first can land after a small one.
- The order on the page is the order in the Store. Delete the old cards first and add the new
  ones in order, rather than trying to reorder.
- The upload input is a hidden `<input type="file">` in the empty card. When driving the page from
  a browser agent, setting files through CDP froze the page renderer; assigning a `File` through
  `DataTransfer` and dispatching `change` worked.
